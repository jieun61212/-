# 법률 원고 스튜디오 · 1차 MVP

법률 블로그 작성 업무를 위한 로컬 웹 앱입니다. 네이버 업로드는 포함하지 않습니다.
Python 3.12+, FastAPI, SQLite, HTML/CSS/JavaScript로 구성했습니다.

Windows 배포 ZIP에서는 압축을 푼 뒤 `처음 설치.cmd`, `프로그램 시작.cmd` 순서로 더블클릭합니다.
Python 3.12 64비트가 필요하며 없으면 공식 설치 페이지를 열어 안내합니다.
필요한 Windows 라이브러리는 ZIP에 포함하고 SHA-256 검사 후 오프라인으로 설치합니다.
자세한 단계는 `윈도우_사용방법.txt`를 참고하세요. 실제 Windows PC 실행은 아직 검증하지 못했습니다.

## 실행

```bash
cd /workspace/-
bash scripts/setup.sh
bash scripts/start.sh
```

기본 포트는 8000이며 루프백에 바인딩합니다. 브라우저 주소 입력란에서 로컬 포트 8000에 접속하세요.
다른 포트는 `LEGAL_BLOG_PORT=8001 bash scripts/start.sh`로 실행합니다.
인증이 없는 개인용 MVP입니다. 외부 공개 시에는 인증과 접근 제어가 필요합니다.

API 키 없이 **예시 모드**로 화면, 규칙 검수, 이력, 복사·내보내기를 사용할 수 있습니다.
예시는 고정된 자료 정리 안내 문단입니다. AI 작성·법률 검색을 실행하지 않으며,
주제별 실제 법률 원고나 PDF 기반 사례를 대신하지 않습니다. 화면·복사·내보내기에 예시 표시를 유지합니다.
예시 모드는 기본 분량에 맞춰져 있습니다. 특정 입력으로 검수에 실패하면 최종본을 표시하지 않습니다.

## 실제 AI 생성

1. 서버 환경변수 `LEGAL_BLOG_API_KEY`에 OpenAI API 키를 설정합니다. 로컬에서는 `OPENAI_API_KEY`도 지원합니다.
2. 선택적으로 `LEGAL_BLOG_MODEL`을 지정합니다. 기본값은 `gpt-4.1-mini`입니다.
   Responses API `web_search`(공식 도메인 필터)와 Chat Completions JSON 출력을 지원해야 합니다.
3. API 인증·결제 및 `api.openai.com` HTTPS 접근이 필요합니다.
4. 서버를 재시작하고 **AI 원고** 모드를 선택합니다.

`.env.example`은 변수 목록 참고용입니다. `.env`를 자동으로 읽지는 않습니다.
OS나 클라우드 환경 설정에서 서버에 변수를 주입하세요. 키를 브라우저·채팅·코드·Git에 넣지 마세요.
AI 모드는 입력과 익명화된 원문을 OpenAI로 전송하며 검색·작성·검수·수정에 API 비용이 발생합니다.

## 기능과 버튼

프로젝트·법인을 선택합니다. PDF가 없을 때만 메인키워드·주제를 직접 입력합니다. 서브키워드·지역·기관·변호사·참고자료·PDF는 선택입니다.
PDF를 첨부하면 메인키워드 후보·선정 키워드·서브키워드·주제를 자동 생성합니다. 사용자가 원문을 익명화하거나 확인 체크를 할 필요가 없습니다. 이미지 작업은 사용자가 별도로 진행하며 프로그램은 판결 분석과 원고의 개인정보를 자동 제거·검수합니다.

AI 흐름: PDF 분석·키워드 자동 선정(첨부 시) → 공식 검색 → 작성 → 규칙 validator → 별도 AI 대조 → 자동 수정·재검수.
최대 3번 수정 후에도 문제가 남으면 실패 상태를 기록하고 내부 원고를 표시·내보내지 않습니다.
최종본에는 제목 후보 3개, 자동 선정 제목, 도입·질문형 본론·체크리스트·결론·CTA가 있습니다.
판결 분석과 공식 출처는 접을 수 있는 영역에 표시합니다.

- **원고 생성**: 왼쪽 현재 입력으로 새 이력을 생성합니다.
- **다시 생성**: 오른쪽 저장 원고의 동일 입력·익명화 PDF로 새 이력을 생성합니다.
- **최종 검수**: 표시된 저장 원고를 재검수하고 필요한 경우 수정합니다. 실패 시 최종본 자격을 해제합니다.
- **복사 / txt 저장 / docx 저장**: 검수 완료 원고만 내보냅니다. 예시 표시는 유지합니다.
- **작성 이력**: 키워드·주제·제목 검색, 프로젝트·법인 필터, 불러오기·삭제를 지원합니다.

PDF 이력을 불러온 뒤 다시 생성은 저장 원문을 사용합니다. 새 입력으로 생성하려면 PDF를 다시 첨부하세요.
이력 삭제는 원고와 저장된 익명화 자료를 함께 삭제합니다.

## 규칙·프롬프트·프로필

| 경로 | 역할 |
| --- | --- |
| `project_rules/rules.json` | 프로젝트 목록·기본 분량·제목 필수 문구 |
| `lawfirm_profiles/profiles.json` | 법인명·연락처·등록 지역 |
| `config/prompts/system.md` | 공통 작성 방식 |
| `config/prompts/rehabilitation.md` | 울(회) |
| `config/prompts/civil.md` | 제공받은 원래 울(민) 지침 |
| `config/prompts/family.md` | 울(혼) |
| `config/prompts/criminal.md` | 울(형) |
| `config/prompts/pdf_analysis.md` / `pdf_article.md` | 판결 분석 / 사례 글 구성 |
| `config/prompts/research.md` | 공식 자료 검색 |
| `config/prompts/review.md` / `repair.md` | 독립 검수 / 자동 수정 |

파일은 요청마다 읽습니다. 수정 후 페이지를 새로 고쳐 목록과 기본값을 갱신하세요.
환경변수 변경에는 서버 재시작이 필요합니다.

울(회)·울(혼)·울(형)은 기본 **공백 제외 1,200~1,800자**입니다.
추가로 제공된 울(민) 지침은 **공백 포함 1,000~1,500자**, 모든 제목에 **민사전문변호사** 포함입니다.
사용자는 분량·공백 계산을 세부 옵션에서 변경할 수 있습니다.
본문 글자 수는 소제목·체크리스트·CTA를 포함하고 제목·분석·검색 메모를 제외합니다.
공백 포함 계산에는 줄바꿈도 포함됩니다. 본문 키워드는 목표 ±1회 허용하며 제목 키워드는 별도로 검사합니다.

생성에는 선택한 법인 프로필만 전달합니다. 다른 법인명·미등록 연락처는 validator에서 차단합니다.
법무법인 시우의 연락처는 미등록 상태이며 확인된 번호를 프로필에 넣기 전까지 만들지 않습니다.
주제 지역은 법인의 등록 소재지를 바꾸지 않습니다.

## 자동 키워드 선정

판결 분석과 검색 의도를 바탕으로 사건 유형·주제 지역에 맞는 메인키워드 후보 3개를 만들고 1개를 자동 선정합니다. 서브키워드 3~6개는 원문 인용 근거를 확인합니다.
검색량 API는 연결되어 있지 않으므로 실제 검색량 수치나 인기 순위는 제공하지 않습니다. 화면에 실제 검색량 미측정을 명시합니다.
PDF 자동 선정과 실제 사례 작성은 AI 모드와 API 키가 필요합니다. 예시 모드는 실제 PDF 분석을 흉내 내지 않습니다.

## 검색·판결 분석의 범위

- 공식 `law.go.kr`, `scourt.go.kr` 도메인만 웹 검색합니다. 검색 호출과 공식 인용이 없으면 생성하지 않습니다.
- 검색 메모와 공식 출처 링크를 저장·표시합니다.
- PDF는 10MB·100쪽·텍스트 40,000자 이하만 지원합니다. 초과 원문을 몰래 자르지 않습니다.
- 텍스트 PDF를 지원합니다. 스캔 PDF는 OCR 후 첨부해야 합니다. 암호화·손상 파일은 오류로 처리합니다.
- 인명·주소·주민번호·연락처·이메일을 자동 처리합니다. 판결 원문에서 식별한 당사자 이름의 지문(해시)을 이용해 글에 이름이 다시 등장해도 제거합니다. 등록된 법인 연락처는 유지합니다. 비정형 개인정보 탐지에는 한계가 있으며 최종 글 검토가 필요합니다. 사용자가 PDF 자체를 수정하는 단계는 없습니다.
- 사건 유형·경위·쟁점·판단·결과·실무상 의미마다 원문 연속 인용을 요구합니다. 인용 불일치·근거 없는 분석은 차단합니다.
- 확인 불가 항목은 추측하지 않습니다. 판결문을 해당 법인의 수임·성공사례로 광고하지 않습니다.
- 별도 AI 검수에서 공식 자료·판결 원문과 대조합니다. 패턴 검사와 AI 검수만으로 사실·법률 정확성, 최신성, 개인정보 제거를 보장하지는 않습니다.
- 게시 전 공식 원문과 최종 원고를 사람이 확인해야 합니다.

## 데이터와 모듈

`data/history.sqlite3`에 날짜(UTC), 프로젝트, 법인, 키워드, 주제, 제목, PDF 여부,
상태, 최종 원고, 입력, 익명화 원문, 판결 분석, 검색 근거, 검수 결과를 저장합니다.
화면 시각은 한국 시간입니다. PDF 원본은 저장하지 않습니다.
`LEGAL_BLOG_DATA_DIR`로 DB 위치를 변경할 수 있습니다. DB는 평문 로컬 파일이고 Git에서 제외됩니다.
민감한 자료의 접근 권한과 보관 정책을 관리하세요.
검색은 부분 검색·주제 단어 검색과 문자열 유사도 정렬입니다. 의미 임베딩 검색은 포함하지 않습니다. 최대 100개 결과를 반환합니다.

`app/`(API·UI·DB), `content_generator/`, `project_rules/`, `lawfirm_profiles/`, `pdf_analyzer/`,
`validator/`, `prompt_builder/`, `exporter/`, `config/`, `logs/`, `scripts/`, `tests/`로 모듈화했습니다.
로그는 원고 ID·모드·수정 횟수·오류 유형만 기록하고 API 키·원문·프롬프트를 기록하지 않습니다.

## 검증

```bash
.venv/bin/python -m unittest discover -v
```

선택적 브라우저 검증(Chromium 별도 설치):

```bash
.venv/bin/python -m pip install -r requirements-dev.txt
CHROMIUM_PATH=/usr/bin/chromium .venv/bin/python -m tests.browser_smoke
```

브라우저 검증은 별도 서버와 임시 DB를 사용하며 실제 API를 호출하지 않습니다.
파이프라인 테스트의 AI 응답도 모의 응답입니다. 실제 AI 생성·공식 검색·한국어 판결 분석은 키와 접근 설정 후 실제 자료로 검증해야 합니다.

이번 MVP 제외 항목: 네이버 업로드, OCR, 다중 사용자 인증, 의미 임베딩 검색.
울(민)은 제공된 지침을 반영했습니다. 다른 프로젝트의 원래 지침은 해당 프롬프트 파일에 보완할 수 있습니다.
